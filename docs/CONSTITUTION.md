# Constitution du Repository "cerebrum-1"

## Préambule

Ce document constitue la loi fondamentale régissant toutes les opérations au sein de ce repository. Tout agent, humain ou artificiel, opérant dans cet espace doit adhérer à ses principes sans exception. L'objectif est de garantir la sécurité, la cohérence et la pérennité du "Livre des Origines".

## Article 1 : Rôle et Finalité (JUNCTURE)

Le repository est le "Livre des Origines", la source de vérité unique et versionnée. Toute action (commit, pull request, suggestion) doit viser à maintenir sa cohérence, sa qualité et sa sécurité. La finalité de chaque contribution est de renforcer cette fondation.

## Article 2 : Principes Directeurs Inviolables

Le fonctionnement de cet écosystème est régi par les protocoles suivants :

### Clause 2.1 - Sécurité (AEGIS)
La détection de toute information sensible (clés d'API, mots de passe) est une priorité absolue. Des alternatives sécurisées (variables d'environnement, secrets) doivent toujours être proposées et implémentées.

### Clause 2.2 - Portabilité (PORTABILITÉ)
L'utilisation de standards ouverts et de technologies durables est obligatoire. L'architecture doit rester agnostique pour garantir sa longévité et son indépendance.

### Clause 2.3 - Résilience (HYGIE)
Aucune logique complexe ne peut être intégrée sans une stratégie de test correspondante. La proposition de tests unitaires ou de validation est une partie intégrante de toute nouvelle fonctionnalité.

### Clause 2.4 - Efficacité (CHRONOS)
Les solutions proposées doivent tendre vers l'efficience algorithmique et structurelle. Les choix techniques doivent être justifiables en termes de performance et de scalabilité.

## Article 3 : Workflow Opérationnel

L'assistance aux opérations se concentre sur les phases de commit et de "Pull Request". Le rôle de tout agent IA est de servir de copilote à la "Barrière Humaine", en fournissant un premier niveau d'analyse et de revue de code automatisée. La décision finale d'intégration (merge) appartient exclusivement à la Barrière Humaine.

## Article 4 : Directives d'Exécution

Toute contribution au code doit respecter les standards suivants :

### Clarté
Le code complexe doit être systématiquement accompagné de commentaires explicatifs.

### Documentation
La création de nouvelles fonctions ou API doit inclure une proposition de documentation (ex: Docstrings, JSDoc).

### Structure
Les contributions doivent respecter l'architecture de dossiers existante :
- `/src` - Code source principal
- `/prompts` - Templates et guides d'usage
- `/docs` - Documentation du projet
- `/tests` - Tests unitaires et d'intégration

*Ce document constitue la base juridique et technique de toutes les opérations dans ce repository. Toute violation de ces principes doit être signalée et corrigée immédiatement.*
